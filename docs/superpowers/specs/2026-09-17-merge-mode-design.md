# Merge-режим: обновление существующей коллекции вместо замены

Дата: 2026-09-17
Статус: утверждённый дизайн

## Контекст и цель

`generate_collection.py` всегда пишет вывод с нуля, полностью заменяя файлы в `dist/`.
Пользователь, который ведёт коллекцию руками (заполняет значения параметров, хранит
токены в окружении, добавляет свои запросы), теряет правки при каждой регенерации.

Цель — режим `--merge`: обновить существующий проект (tree / bundled / postman-v3),
не заменяя пользовательские данные. Новые методы добавляются, описания актуализируются
из схемы, коллекция пересортировывается. Дополнительный флаг `--prune` (работает
и с `--merge`, и без него) удаляет запросы и папки, отсутствующие в новой схеме.

## Область

Форматы: `tree` (Bruno/OpenCollection), `bundled`, `postman-v3` (Native Git дерево).
Не поддерживается: `postman` (v2.1 JSON — файл только для импорта), `openapi`.

Дефолтное поведение без флага не меняется — полная замена.

## Подход

Merge в пространстве внутренней модели (collection dict), не на уровне файлов:

1. `build()` строит новую модель как обычно.
2. Обратные загрузчики читают существующий вывод в модель (или её фрагменты).
3. `merge(new, old)` применяет правила защиты пользовательских данных.
4. Существующие writers (`write_tree`, bundled-запись, `write_postman_v3`) пишут
   результат без изменений. Writers ничего не удаляют, поэтому методы, удалённые
   из схемы, и пользовательские файлы остаются на диске автоматически.

Обратные загрузчики:

- **bundled** — `yaml.safe_load` файла; модель совпадает с документом (убрать ключ
  `bundled`).
- **tree** — `opencollection.yml` (корень без items), `environments/*.yml` →
  `config.environments`, в каждой папке `folder.yml` + остальные `*.yml` как запросы
  (полная модель: пользовательские ключи сохраняются и перезаписываются).
- **postman-v3** — частичная загрузка: `postman/collections/<Name>/*/*.request.yaml`
  (строки body по именам файлов), `postman/environments/*.environment.yaml`
  (значения переменных), `collections/<Name>/.resources/definition.yaml`
  (коллекционные variables). Формат v3 не round-trip полной модели: сохраняются
  только защищаемые слоты (значения строк, значения переменных), не неизвестные
  пользовательские ключи.

## Правила merge

Единое правило для защищаемых слотов: **старое значение сохраняется, если оно
отличается от генерируемого; если не отличается — замена ничего не меняет.**

Защищаемые слоты:

| Слот | Сопоставление | Защищаются |
| --- | --- | --- |
| `http.body.data[].value` | по имени параметра | `value`, `disabled` |
| env-переменная (`config.environments[].variables[]`) | по имени | `value` |
| коллекционная переменная (`request.variables[]`) | по имени | `value` |

Исключение: переменная с именем `apiVersion` всегда берётся из генерации — её
значение меняется от запуска к запуску (версия схемы), старое всегда «отличается»,
без исключения версия застрянет устаревшей.

Всё остальное регенерируется: `info`, `docs`, описания методов и параметров,
`http.url`/`method`/`auth`, структура body, новые параметры, сортировка, `seq`.

Прочее:

- Строки body, которых нет в новой схеме, — сохраняются, ставятся в конец перед
  строкой `v`.
- Переменные/запросы/папки, которых нет в новой схеме, — сохраняются (без `--prune`).
- Пользовательское состояние `disabled` у существующей строки сохраняется
  (переключённый параметр не возвращается к схемному состоянию); у новых строк —
  из схемы.
- `description` существующих строк обновляется из схемы.
- Папки и запросы пересортировываются целиком по алфавиту, `seq`/`order`
  перенумеровываются; `meta_folder` остаётся первой. Пользовательские элементы
  втягиваются в общую сортировку. У файлов методов, удалённых из схемы (и у
  пользовательских файлов), старые `seq`/`order` не актуализируются — остаются
  как есть.

### `--prune`

Удаляет всё, чего нет в новой схеме: старые запросы и целые папки, включая
пользовательские запросы в сгенерированных папках (отличить «пропал из схемы» от
«добавлен вручную» невозможно — правило единообразное). Свой контент держите вне
сгенерированных папок или не используйте `--prune`. Env-переменные и коллекционные
переменные prune не трогает.

- С `--merge`: merge с `prune=True` выбрасывает old-only элементы из модели.
- Без `--merge`: модель и так строится только из схемы, prune — только физическая
  чистка файлов-сиротов, оставшихся от прошлых генераций (переименованные/удалённые
  методы).
- После записи удаляются файлы-сироты: в tree — `*.yml` запросов и опустевшие папки,
  в postman-v3 — `*.request.yaml` и папки с их `.resources`; в bundled документ
  всегда переписывается из модели целиком — физически удалять нечего.

## Компоненты и поток

Новый модуль `merge_collection.py` (не импортирует `generate_collection` — без цикла):

- `load_existing(out_path, fmt) -> collection | None` — диспетчер загрузчиков:
  `load_bundled`, `load_tree`, `load_postman_v3`.
- `merge(new, old) -> (collection, stats)` — правила выше.

`generate_collection.main()` получает флаги `--merge` и `--prune`:

- флаги независимы: `--prune` без `--merge` — полная регенерация + чистка
  файлов-сиротов;
- для `tree|bundled|postman-v3`: при `--merge` после `build()` загрузить
  существующий вывод из `args.out` и смержить (с prune или без); если вывода нет —
  обычная генерация;
- после записи при `--prune` — удаление файлов-сиротов;
- для `postman|openapi`: ошибка `--merge/--prune are only supported for tree, bundled and postman-v3`.

Документация: README — строка о `--merge`/`--prune` в таблице скриптов и раздел
«Обновление существующей коллекции».

## Статистика

В итоговую строку добавляются счётчики:
`added= updated= kept= pruned= preserved_values= preserved_disabled=`
(new methods / регенерированные существующие / old-only сохранённые / old-only удалённые при `--prune`).

## Ограничения

- postman-v3: неизвестные пользовательские ключи YAML не переносятся (writer всегда
  переизлучает v3-форму из модели); tree/bundled переносят всё.
- Writers не удаляют файлы: без `--prune` переименованные в схеме методы оставляют
  старый файл (появится и новый); с `--prune` старый удаляется.
- `seq`/`order` у сохранённых old-only файлов могут дублироваться с новыми — на
  работу не влияет, порядок в Bruno/v3 определяется в основном именем файла/позицией.
- `--prune` в сгенерированных папках удаляет и пользовательские запросы (см. выше).

## Тесты

- Unit (правила merge): защита значения body при отличии; пропуск при совпадении;
  `disabled` пользователя; `apiVersion` из генерации; env-значение; новые строки;
  old-only строки перед `v`; old-only переменные/запросы/папки; пересортировка и
  перенумерация `seq`.
- Unit (загрузчики): round-trip tree/bundled; частичная загрузка v3.
- Integration на каждый формат: генерация → ручные правки (значение параметра,
  переключённый `disabled`, своя строка body, токен в env, свой запрос/папка) →
  `--merge` → ассерты на сохранность и обновления; вывод валидируется
  `validate_collection.py`.
- Prune: `--merge --prune` удаляет пропавший метод (файл на диске исчезает),
  опустевшую папку, пользовательский запрос в сгенерированной папке; env-переменные
  не трогает; `--prune` без `--merge` — чистка файлов-сиротов после полной
  регенерации.
- `--merge` без существующего вывода = свежая генерация; `--merge` с
  `postman|openapi` → ошибка; без флага поведение не меняется (замена).

## Не входит

- Merge для `postman` v2.1 и `openapi`.
- Перенос пользовательских `scripts` из request-файлов (регенерируются).
- Prune для env-переменных и маркер «сгенерировано» для выборочного удаления.
